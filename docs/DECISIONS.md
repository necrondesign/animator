# Решения по проекту

Журнал ключевых решений: что выбрали и почему. Новые записи добавляются сверху.

## 2026-10-16 — Безопасность, этап 2: доверие к проекту и план

Разведка показала: `code.js` проекта загружается обычным `require` не только в окнах редактора, но и в фоновом
Node-процессе plumbing (сохранение, экспорт), там же вычисляются выражения. Поэтому изоляция окон сама по себе чужой
проект не обезопасит. План:
- **2a (сделано):** предупреждение о доверии при открытии проекта, как Workspace Trust в редакторах кода. Режима
  «открыть без выполнения кода» пока нет — его даст 2b, поэтому выбор только «открыть» или «отмена».
- **2b:** разбирать `code.js` как данные и отклонять всё вне формата анимации — открытие перестанет выполнять код.
- **2c:** выражения и обработчики событий — только в песочнице (окна без Node), включая рендер экспорта.
- **2d:** изоляция окон интерфейса и перенос файловых операций модели в главный процесс/plumbing.

**Решение 2026-10-16: этапы 2b–2d отложены**, предупреждения о доверии пока достаточно; приоритет — `@haiku/core`.
Находка для будущего: `code.js` может содержать собственный код пользователя до и после `module.exports`
(Haiku сохранял его при перезаписи). Строгая загрузка «только данных» сломала бы такие проекты, поэтому при возврате к
теме варианты такие: «безопасный режим» только для недоверенных проектов (как Restricted Mode в VS Code: смотреть
без выполнения кода) или полная песочница для всего кода проектов.

## 2026-10-16 — Безопасность окон, этап 1

Полная изоляция (`contextIsolation`, `sandbox`) сейчас невозможна без перестройки: модель проекта
(haiku-serialization) работает прямо в окнах редактора и загружает `code.js` проекта через `require`. Поэтому сначала
закрыт самый опасный путь — попадание **чужой** страницы в окно с доступом к Node:
- переход окна на любой адрес, кроме страниц самого приложения, блокируется (ссылка открывается во внешнем браузере);
- `window.open` запрещён, `<webview>` разрешён только для страниц Glass/Timeline, preload у него убирается;
- запросы разрешений (камера, микрофон, уведомления и т.д.) отклоняются;
- `@electron/remote` заменён IPC-мостом: окно просит главный процесс показать диалог или меню, а не получает доступ
  ко всему API главного процесса. Контекстное меню передаётся описанием, главный процесс возвращает id выбранного
  пункта, обработчик выполняется в окне.

Этап 2 (вынос модели проекта из окон и включение изоляции) — отдельная большая задача.

## 2026-10-16 — Линтер: ESLint вместо tslint

- **ESLint 10 + typescript-eslint + @stylistic**, один flat-конфиг в корне (`eslint.config.mjs`). Без
  eslint-plugin-react: он пока не поддерживает ESLint 10, а парсер typescript-eslint и так видит использование
  компонентов в JSX; правила для хуков к коду на React 15 неприменимы.
- **Правила описывают существующий стиль** (`if (`, `name (args)`, 2 пробела, одинарные кавычки, `{a}` без
  пробелов, висячие запятые, 120 символов для TS), чтобы линтер не требовал переформатировать код. Автоисправления
  (только пробелы, точки с запятой, `let` → `const`) применены один раз при переходе.
- **Проверка и исправление разделены.** `yarn lint` только сообщает о проблемах; `yarn lint:fix` — явная
  команда. Старый `yarn lint-all` молча запускал `tslint --fix` и переформатировал сотни файлов.
- **Вендорный и сгенерированный код не проверяется**: копия fs-extra, режимы CodeMirror, SVGO-плагин, фикстуры,
  демо-проекты, входные данные тестов.
- **Правила, которые старый код нарушает массово** (`require`, `any`, `@ts-ignore`, `hasOwnProperty`,
  `case`-объявления и др.), выключены с пометкой в конфиге — включать по одному вместе с правками.

## 2026-10-15 — Фаза 3: Figma, буфер обмена, ошибки, фича-флаги

### Figma: вставка SVG как основной путь, токен — опция
OAuth шёл через сервер Haiku и умер вместе с ним. Варианты: личный токен Figma, плагин для
Figma, копирование. Выбрали:
- **Copy as SVG → Ctrl+V** на холсте — без токена, сети и аккаунта; работает с SVG из любой
  программы. Файл сохраняется в `designs/Pasted N.svg`, так что ассет остаётся в проекте.
- **Импорт файла по ссылке** с личным токеном (`X-Figma-Token`) — для импорта целого файла и
  обновления. Токен хранится только локально (`~/.haiku`), при 403 сбрасывается.
- **Плагин для Figma** — позже (Фаза 5): нужна публикация в Figma Community и мост в приложение.

### Буфер обмена через IPC
В Electron 44 у рендереров нет `clipboard`, а в основном процессе он асинхронный. Рендереры
обращаются к буферу через `ipcRenderer.invoke` (обработчики в `haiku-creator/src/electron.js`),
а не через `@electron/remote`: remote всё равно уходит в Фазе 4 (безопасность рендереров).

### Ошибки: только локально, без Raven
Raven/Sentry, Carbonite и Mixpanel удалены вместе с npm-зависимостями. Как теперь видны ошибки:
- **Creator** сам показывает свои необработанные ошибки и отклонённые промисы как уведомления;
- **Glass/Timeline**: их ошибки попадают в консоль webview, Creator показывает их (`webviewConsole.js`);
- **plumbing**: `errorReporting.js` ловит `uncaughtException`/`unhandledRejection`, пишет в лог и
  через ERROR_CHANNEL отправляет в Creator. Процесс продолжает работать, чтобы можно было сохраниться.
Попутно в `createNotice` убраны две ловушки: уведомление, пришедшее в течение 500 мс после
предыдущего, молча терялось; после 25 одинаковых ошибок окно закрывалось (с потерей работы).

### Фича-флаги
17 флагов, включённых всегда, стали обычным поведением. Механизм экспериментов оставлен для 3
выключенных (`AllowBitmapImages`, `OutliningElementsOnStageFromStage`, `WindowMenu`) — их
судьбу решаем отдельно: включить, доделать или удалить код.

## 2026-10-15 — Название: motion-side

Продукт называется **motion-side** (как написано: строчными, через дефис).
- Рабочее название «Animotion» отклонено: в App Store несколько приложений для анимации с этим
  именем (включая Lottie-просмотрщик «Animotion X»), npm-пакет `animotion` занят.
- Для «motion-side» совпадений не найдено (веб, GitHub, npm на 2026-10-15). Это не юридическая
  проверка товарного знака — её стоит сделать перед коммерческим использованием.
- Где что меняется: имя, протокол и ссылки — `packages/haiku-common/src/branding.ts`;
  `productName` и `build` (appId `io.github.necrondesign.motion-side`, протокол) — корневой
  `package.json`; иконки и фон установщика — `build/` (исходники в SVG).
- Не переименовываем: пакеты `@haiku/core` и `haiku-*`, формат проектов, атрибуты `haiku-id`,
  тему редактора кода — это внутренние идентификаторы, от них зависит совместимость со
  старыми проектами и встроенными компонентами.
- Иконка временная: кривая движения между ключевыми кадрами. Можно заменить, перерисовав
  `build/icon.svg`.

## 2026-10-11 — Итоги Фазы 2 (Electron)

Electron 2.0.8 (2018) → **44.4.5**: приложение работает нативно на Apple Silicon (Node 24 внутри),
x64/Rosetta больше не нужен. Проверено реальным запуском: `yarn smoke` поднимает редактор на тестовом
проекте (Creator + Glass + Timeline), делает снимок окна и рендерит кадр через «пекарню» экспорта;
то же самое проходит на собранном `Haiku.app` (arm64) из `yarn dist:dir`.

Что сделано:
1. **Совместимость рендереров без переписывания UI.** Окна и `<webview>` явно получают прежние
   настройки (Node в рендерере, без contextIsolation и sandbox), `remote` → `@electron/remote`.
   Перевод на IPC + preload — отдельная задача (Фаза 4), это осознанный долг безопасности.
2. **API, изменившиеся за 42 мажорные версии:** синхронные диалоги → `*Sync` после `ready`,
   колбэки диалогов → Promise, `shell.openItem` → `openPath`, `makeSingleInstance` →
   `requestSingleInstanceLock`, `registerFileProtocol` → `protocol.handle`, `capturePage` → Promise,
   zoom-лимиты, типы меню.
3. **Стартовые диалоги** теперь можно пропустить через `HAIKU_PROJECT_FOLDER` (так `yarn start` со
   сценариями снова открывает выбранный проект); выход по «Exit» — `app.exit` вместо
   `process.kill(0)`, который убивал всю группу процессов, включая терминал.
4. **Автообновление удалено** (Windows `electron-updater` и Mac Squirrel на серверах Haiku).
   Проверка обновлений через GitHub Releases — будущая задача.
5. **Упаковка:** electron-builder 26 собирает прямо из монорепозитория; подпись и нотаризация
   опциональны (`@electron/notarize`, свои ключи Apple); цели — macOS dmg/zip (arm64 + x64),
   Windows NSIS, Linux AppImage/deb. Релизы — `.github/workflows/release.yml` по тегу `v*`
   (черновик GitHub Release со ссылкой на исходники, AGPL §6).
6. **e2e вместо Spectron:** `scripts/smoke.js` на Playwright, также в CI на macOS и Linux.

### Баги, найденные реальным запуском
- «Пекарня» экспорта импортировала логгер как default-экспорт CommonJS-модуля: любая ошибка
  рендера кадра роняла обработчик IPC, и экспорт зависал навсегда (баг оригинала).
- Ошибки рендера кадра глушились молча; теперь текст ошибки попадает в лог.

### Перед первым публичным релизом нужно решить
- **Название и appId.** Сейчас `productName: "Haiku"`, `appId: com.Haiku...`. Публиковать сборки под
  именем Haiku нельзя (LICENSING.md, правило 8) — нужен свой бренд.
- Предупреждения редактор показывает пользователю как красные «Error»-плашки даже в production —
  разобрать в Фазе 3.

## 2026-10-11 — Итоги Фазы 1 (чтобы собиралось)

Результат: чистый `yarn install` со всеми скриптами проходит на macOS arm64 / Node 24 без
Python и node-gyp; `compile-all`, `typecheck-all`, `test-all` зелёные (14 пакетов, 1112 тестов).

Что сделано:
1. **Нативные модули убраны.** `nodegit` → `isomorphic-git` (чистый JS, MIT): локальные
   init/status/add/commit/теги/reset работают как раньше, облачные clone/fetch/push/merge
   (серверы Haiku) явно возвращают «не поддерживается». `@ronomon/base64` → `Buffer`,
   `chokidar` 1 → 3, `ffmpeg-static` 2 → 5 (есть arm64), webpack 4 → 5 и nodemon 1 → 3 (ушёл
   последний `fsevents` 1.x).
2. **Инструменты:** Node 24 LTS (`.nvmrc`, `engines`), yarn 1.22.22 через `packageManager`
   (corepack), TypeScript 5.9.3 + ts-node 10 + tsconfig-paths 4, `@types/node` 24.
3. **Тесты честные и изолированные:** `test-all` падает при любой ошибке; убран `|| true`;
   тесты больше не пишут в реальную `~/.haiku` (preload `haiku-testing/isolate-home`);
   типы тестов проверяет отдельный `typecheck-all`. Spectron (мёртв) удалён.
4. **CI:** GitHub Actions на macOS arm64 и Linux (`.github/workflows/ci.yml`).

### Почему TypeScript 5.9, а не 7
TypeScript 7 — новый компилятор на Go без JS API: с ним не работают ts-node и ts-loader,
на которых сейчас держатся тесты и демо. Переход — после ухода с ts-node (Фаза 4).

### tslint оставлен до Фазы 4
tslint устарел; с TS 5.9 его правила из `tslint-eslint-rules` падают с исключениями (проверено
2026-10-15), то есть линтер фактически не работает. Заменён на ESLint 2026-10-16 (см. запись выше).

### Временная мера: x64 Electron на Apple Silicon
Electron 2.0.8 не имеет arm64-сборки, поэтому на Apple Silicon ставится x64-бинарник
(`npm_config_arch=x64 yarn install`), который работает через Rosetta. Уберём в Фазе 2.

### Найдено по пути
- Тесты раньше писали в реальную `~/.haiku` разработчика (registry.json, auth).
- `Error.ts`: метаданные ошибки читаются как `data.exception[0]`, а у Sentry формат
  `exception.values[0]` — сообщение всегда «Unknown». Уйдёт вместе с Raven в Фазе 3.

## 2026-10-11 — Фокус и платформа

### Фокус: интерактивные веб-компоненты
Главный сценарий — интерактивные анимации для веба: рантайм `@haiku/core`, адаптеры
React/Vue/vanilla, states, expressions, actions.

Что из этого следует:
- `@haiku/core` модернизируем глубоко: ESM, без IE-кода, React 18+ на хуках, Vue 3,
  безопасный режим expressions (без `new Function`), никакой телеметрии в бандле.
- Развиваем интерактивность: модель State Machine (по образцу Rive), spring-easing.
- Lottie, GIF и MP4 остаются и поддерживаются, но не главный приоритет; Lottie-экспорт
  чиним (баги, корректность), новые фичи Lottie — позже.
- Angular-адаптер (Angular 6) — кандидат на удаление или переписывание; решить в Фазе 4.

### Платформа: остаёмся на Electron и обновляем его
Код сильно завязан на Node (plumbing, git, ffmpeg, файловая система). Поэтапное
обновление Electron до актуальной версии — самый быстрый путь к рабочим сборкам под
macOS (включая Apple Silicon), Windows и Linux. Tauri и веб-версию не рассматриваем на
этом этапе; можно вернуться к вопросу после Фазы 4.
